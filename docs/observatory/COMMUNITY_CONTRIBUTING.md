# Community corrections and contributions

Contributions may propose a source correction, missing venue, policy-date source, linkage error, takedown, or new adapter. Every proposal must name its evidence URL or public fixture, source licence, affected canonical IDs, expected population/stage, observability grade, tests, and prohibited-use acknowledgement.

Canonical data are immutable during review. A contribution first creates a candidate provenance event, runs schema/count/licence/privacy tests, and receives an independent validation status. Only a new snapshot can promote it. Corrections never overwrite a frozen release; they produce a tombstone or superseding record plus a release diff.

Contributors agree not to infer anonymous reviewer identities, rank individuals, expose contact data, use paid/proprietary data APIs, or introduce outcome leakage into benchmark features. Reports should use the repository's structured issue forms in `docs/observatory/issue_templates/`.
